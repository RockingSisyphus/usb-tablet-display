# 工作流说明（中文）

本项目由 8 个 VibeFlow 工作流组成。每个工作流都能单独校验、单独执行、单独审阅；
常驻的那个负责日常自动化，其余的一次性工作流是它调用的"动作"或给人手动使用的入口。

项目现在有两个 root：

- `usb_tablet_display/`：日常运行（常驻、连接、断开、联网）
- `usb_tablet_maintenance/`：维护类（状态、检查副屏、保护检查、安装）
- `nodes/`：两个 root 共用的业务节点（设置、状态读取、设备探测、副屏判断）

## 常驻程序（configs/daemon.jsonc）
一直运行的小服务。每一轮都在做同一件事：读取设置与状态 → 检查平板 → 定期检查网络 →
查看后台任务 → 处理用户命令 → 检查是否正在投屏 → 决定要做什么 → 必要时执行连接或断开 → 推进一轮循环。
它自己不直接操作底层，而是把"连接/断开"交给下面已验证的工作流在后台执行，因此不会卡住。

## 一次性动作

| 工作流 | 什么时候用 | 做什么 |
| --- | --- | --- |
| 连接（connect.jsonc） | 插入平板、点"启用"、自动恢复时 | 检查平板可用 → 打开副屏 → 配置并启动串流 → 授权录屏 → 让平板开始投屏 → 确认画面已连上，失败会明确报错 |
| 断开（disconnect.jsonc） | 拔线、点"关闭"时 | 先停串流（避免移除正在传输的屏幕）→ 撤销虚拟副屏 → 确认已撤销 |
| 状态（维护 root：status.jsonc） | 想了解现在什么情况时 | 只读：检查平板、副屏、串流、网络，汇总成一份状态 |
| 联网（internet.jsonc） | 手动检查/修复平板上网 | 确保平板通过 USB 共享电脑网络，并实际测试能否上网 |
| 检查副屏（维护 root：display-check.jsonc） | 排查副屏没出来时 | 只读：比较当前屏幕布局和期望状态，判断差在哪 |
| 保护检查（维护 root：guard-check.jsonc） | 验证"不会误删屏幕"的保护 | 尝试一次未确认的关闭，确认被安全拒绝 |
| 安装（维护 root：install.jsonc） | 首次部署、升级、回滚 | `all` 一键安装；也可分别执行 备份 / 停止服务 / 安装 / 还原 / 自检 |

## 常用积木（子图与节点）

- 读取设置与状态 / 检查平板状态：所有流程共用的开局，保证后面拿到同样的设置与状态。
- 检查副屏是否已就位、调整副屏：负责"副屏开没开、要不要调"，调整失败会自动回滚。
- 配置/启动/停止串流、授权录屏、确认画面在传输：负责电脑端把画面送到平板这一整条链路。
- 让平板开始投屏：负责在平板上登记电脑地址并打开投屏程序。
- 检查是否正在投屏、决定要做什么、执行连接或断开、查看会话结果、处理用户命令：常驻程序的大脑。
- 同步平板网络、定期检查网络：负责平板上网。
- 执行安装操作：负责部署与回滚。
