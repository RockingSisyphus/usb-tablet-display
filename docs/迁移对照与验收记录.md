## 事故记录：2026-11-01 15:21–15:22 图形会话退出

- 触发：本人（助手）为验证 teardown，直接调用 `org.gnome.Mutter.DisplayConfig.ApplyMonitorsConfig`（method=2，持久）移除虚拟输出 DP-1。
- 15:21:21 调用发出；15:21:22 `gnome-shell[10544]` 立即报 `meta_display_get_monitor_in_fullscreen: assertion 'monitor >= 0 && monitor < n_logical_monitors' failed`，同时出现 BoxPointer 已释放、Betterbird 子表面无法映射等一连串窗口销毁告警；15:22:41 systemd-logind `Removed session 116`，图形会话结束退出到登录界面。
- 结论（15:43 复核后更正）：**不是**全屏窗口，而是 **Sunshine 仍在通过 PipeWire screen-cast 抓取 DP-1**。同秒日志中的致命行是 `meta-screen-cast-monitor-stream-src.c:735: meta_screen_cast_monitor_stream_src_record_to_framebuffer: assertion failed: (renderer_view != NULL)` 与 `Bail out! libmutter`，即 shell 目录主动 abort；`meta_display_get_monitor_in_fullscreen` 只是同秒的伴生告警。
- 旧实现不崩的原因：`disable_display()` 先 `stop_sunshine()` 再 `apply_display("disable")`，移除显示器时已无活跃 screen-cast。插拔平板走的是内核热插拔路径，同样不涉及"抓取中的流指向已消失的显示器"。
- **不是** monitors.xml 被改写（mtime 仍为 2026-10-30 23:52），也不是 systemd 单元操作。
- 恢复情况：重新登录后 DP-1 与 eDP-1 均处于活动状态，`enable_matches=True`；旧 `android-tablet-controller`/`internet` 单元仍为 inactive（由本人先前停止）。
- 后续约束（写入 connect/teardown 设计）：
  1. 任何 `ApplyMonitorsConfig` 前必须检测全屏窗口；存在则绝不改变显示器集合。
  2. 优先使用 method=1（临时）并在用户确认后持久化；或先执行 verify 流程。
  3. 禁止把活动显示器数量降为 0；移除视频输出前需要显式确认。
  4. 自动化测试不得在用户正在使用的会话里直接执行 teardown；改在无全屏应用时或独立会话进行。
