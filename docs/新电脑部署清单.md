# 新电脑部署清单

## 一键安装

```bash
python3 cli/main.py install all
```

它会依次完成：安装三个用户单元（协调服务 / 常驻程序 / 联网）、写 `~/.local/bin/usb-tablet`、
拷贝并启用 GNOME 扩展、缺省时生成配置、安装平板端 gnirehtet App（平板已连接时）、
最后做一次依赖自检并列出缺失项。

只想检查环境：

```bash
usb-tablet install verify
```

## 需要用户自己准备（安装程序不代劳）

| 依赖 | 说明 |
|---|---|
| Python ≥ 3.11 | 需要 `tomllib` |
| PyGObject（`python3-gi`） | 显示器与桌面集成 |
| adb（platform-tools） | 访问平板；需要 udev 规则才能免 sudo |
| Sunshine | 串流服务端，需先安装并**至少运行一次**（生成 portal token） |
| GNOME Shell + Mutter | 副屏布局与录屏授权 |
| NetworkManager | 需要能创建名为 `android-usb-direct` 的连接 |
| 平板侧 Moonlight | 投屏客户端 |
| 平板 USB 调试 | 在开发者选项里打开并授权本机 |

## 虚拟副屏

虚拟副屏由 **EDID 覆盖**创建，不是 Sunshine 创建的（Sunshine/Moonlight 只负责串流）。
`install` 会自动处理：写入 `install/edid/virtual-display.bin`、在
`/etc/default/grub` 补齐 `drm.edid_firmware=DP-1:edid/virtual-display.bin video=DP-1:e`、
执行 `update-grub`。**需要 sudo，且重启后生效。** 已就绪的机器会跳过这一步。

## 网络配置（缺省时）

`install all` 的自检会在缺少 `android-usb-direct` 时给出提示，可执行：

```bash
nmcli connection add type ethernet ifname '*' con-name android-usb-direct \
  ipv4.method auto ipv4.never-default yes ipv4.ignore-auto-routes yes \
  ipv4.ignore-auto-dns yes ipv6.method disabled
```

## 自动填写的配置

`install` 会尽量自动填好 `tablet.toml`：

- `serial`：当 `adb devices` 里**只有一台**设备时，自动写入它的序列号
- `host_name`：自动写入当前电脑的主机名

其余字段（`connector`、`app_id`、`connection`）保留模板默认值，需要时手动调整。

## 每台机器要改的配置

`~/.config/usb-tablet-display/tablet.toml`：

| 字段 | 含义 |
|---|---|
| `serial` | 平板的 adb 序列号（`adb devices` 第一列） |
| `host_name` | 电脑在 Moonlight 里显示的名字 |
| `connector` | 虚拟副屏的接口名，通常 `DP-1` |
| `app_id` | Moonlight 里该电脑条目的应用 ID（首次连接后由程序登记） |
| `connection` | NetworkManager 连接名，默认 `android-usb-direct` |

## 图形控制面板

安装会写入 `~/.local/share/applications/usb-tablet-display.desktop`，
应用列表里出现「USB 平板副屏」；也可以命令行执行 `usb-tablet gui`。
面板通过命令行查询状态、提交开关请求，不直接操作底层。

## 安装后确认

```bash
usb-tablet status      # 应看到 present / device / enabled / connected / ok
./tools/verify.sh      # 项目门禁：8 份工作流 + 测试
```

## 回滚

```bash
usb-tablet install restore      # 配合 USB_TABLET_BACKUP 指向备份目录
```
